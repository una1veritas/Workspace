# 点列から人数を数える

2枚の点列（1つの点が1人）から、写っている人数を数えるプログラムです。
卒業研究の手法（2枚の点列を射影したヒストグラムの形で重ね方を探し、重ねて同じ人を組にする）を、点列の画像に当てはめます。
写真から点列を作る部分（顔検出）は含みません。

## 動かし方

```
pip install -r requirements.txt
python count_people.py
```

Python 3（3.12 で確かめました）と、numpy・scipy・matplotlib を使います。1組あたり数秒で終わります。

読む画像は、`count_people.py` の先頭近くにある次の2行に書いてあります（いまは例1）。別の画像で試すときは、この2行を書き換えます。

```python
IMAGE_P = "examples/example1_standard_P.png"    # 1枚目（白地に黒い点）
IMAGE_Q = "examples/example1_standard_Q.png"    # 2枚目（1枚目と同じ大きさ）
```

パスは `count_people.py` のあるフォルダから見たものです。`C:/...` のような絶対パスでもかまいません。

## 入力

- 白地に黒い点を打った画像2枚（PNG）。1つの点が1人です。2枚は同じ大きさにします。
- 2枚は、同じ教室を「横に大きく（視野の半分ほど）、縦に少し（座席1行以内）」ずらして撮ったものにあたります。
  倍率は 0.9〜1.1 倍、傾き（せん断・ロール）は小さい範囲だけを探します。この範囲を外れる2枚では、重ね方を見つけられません。
- 点が重なって1つに見えると、1人として数えます。ほかの点の2倍より大きい点があれば、注意を出します。

## 出力

画面に、人数と途中の値を出します。例1 では次のようになります（説明の行は省いています）。

```
人数 70 人

一番よい重ね方（変換 T）
  P の点 (x, y) は、Q では (x', y') に写る
    x' = 0.9387 x − 0.0665 y − 445.8
    y' = 0.0293 x + 0.9482 y − 42.4

同じ人の組
  組になった人 20 人 → 人数 = 38 + 52 − 20 = 70
  一致率 1.00（Q の視野に写った P の点 20 のうち、組になった割合）

許容 ε
    ・R = 8.7 px
    ・その Q の点から、一番近いほかの Q の点までの距離の半分
  解像できない点 0 個
```

### 出力の読み方

- **変換 T**：P の点 (x, y) が、Q のどこに写るかを表します。x は画像の左端から右へ、y は上端から下へ測った位置です（単位は画素）。
  - x' の式：x の前の数は横の倍率、y の前の数は「下の行ほど横にずれる」度合い（せん断・ロール）
  - y' の式：x の前の数は「右の列ほど縦にずれる」度合い（ロール）、y の前の数は縦の倍率
  - 最後の数：P の左上の隅 (0, 0) が Q で写る位置（2枚のずれ）
- **一致率**：Q の視野に写った P の点のうち、組になった割合です。正しく重なっていれば 1 に近くなります。
- **許容 ε**：T で写した P の点と Q の点が ε 以内なら、同じ人として組にします（1人は1つの組だけ）。ε は Q の点ごとに、次の2つの小さいほうです。
  - **R**：重ね方の候補ごとに「写した P の点から、一番近い Q の点までの距離」の最大を測り、その一番小さい値です（視野に5人以上が写る候補に限る）。
    正しく重ねれば、写した P の人のそばには Q の同じ人が必ずいるので、この最大は小さくなります。誤った重ね方では、どこかの点が人のいない所に落ちて大きくなります。
    そこで一番小さい値を、「正しく重ねても、同じ人どうしがこれだけ離れうる」という見積もりにします。
  - **最近傍の半分**：その Q の点から、一番近いほかの Q の点までの距離の半分です。
    写した点がこれより近ければ、その Q の点が一番近い点だと保証されます（ほかの Q の点は、もっと離れている）。だから、隣の人と取り違えません。
- **解像できない点**：R が「最近傍の半分」より大きい Q の点です。同じ人のずれを吸収するには R まで許す必要がありますが、その範囲には隣の人も入りえます。
  そのため、同じ人か隣の人かを決められません。この点は組にせず、人数を範囲で答える理由になります。

### 1つに決められないとき

- 1つに決められないときは「人数 70〜73 人」のように範囲で答えます。理由は次の2つです。
  - 重ね方の候補が複数残り、どれが正しいか決めきれない
  - 近くの人どうしが近すぎて、同じ人か別の人か決められない点がある
- 重ね方を見つけられないときは「人数を決められなかった」と答えます。誤った人数を出すより、決められないと答えることを優先しています。

### 確認用の図

確認用の図 `<例>_result.png` も、1枚目の画像と同じフォルダに書き出します。上の段が入力の2枚、下の段が重ね合わせです。緑の線で結んだ組を同じ人とみなしています。
灰色の四角は「解像できない点」（近くの人どうしが近すぎて、同じ人か別の人か決められない点）です。

## 手法の流れ

1. **重ね方の候補を探す**：2枚の点列を横と縦に射影したヒストグラムの形（正規化相互相関）を比べ、重ね方 T（アフィン変換）の候補を粗く探す
2. **重ね方を詰める**：ビン幅を半分ずつ狭めて T を詰め、近い点どうしの仮の組から、最小二乗で T を当て直す
3. **同じ人を組にする**：T で重ね、許容 ε 以内の点どうしを同じ人として組にする（二部グラフの最大マッチング）。
   ε は点ごとに「その点の最近傍までの距離の半分」と「重ねたときのずれの最大 R」の小さいほう（上の「出力の読み方」）
4. **数える**：組になった割合（一致率）で候補を選び、人数 = 1枚目の点の数 + 2枚目の点の数 − 組の数

## 入力例

`examples/` に、合成データで作った5組があります。`<例>_ground_truth.txt` に正しい人数と、2枚を重ねる正しい変換を書いてあります。
入力例は `python make_example_images.py` で作り直せます。

| 例（ファイル名） | 中身 | 正しい人数 | このプログラムの出力 |
|---|---|---|---|
| `example1_standard` | 標準 | 70 人 | 70 人 |
| `example2_vertical_shift_one_row` | 縦のずれ1行 | 55 人 | 55 人 |
| `example3_nearly_full` | 満席に近い | 76 人 | 76 人 |
| `example4_sparse` | まばら | 44 人 | 44 人 |
| `example5_large_detection_error` | 検出のずれが大きい | 66 人 | 66〜68 人（近くの人どうしを解像できず、範囲で答えた） |

## 限り

- 値（ビン幅、一致度の下限など）は、合成データで決めたものです。実際の教室で確かめた値ではありません。
- 人の検出は完全（見落としも誤検出もない）と仮定しています。
- 座り方が規則正しい教室では、外れやすいことが分かっています。誤った重ね方の候補が、R を小さく決めてしまうためで、いま検討しています。
